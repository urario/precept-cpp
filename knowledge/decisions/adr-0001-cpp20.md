# Context

Precept's first release expresses size preconditions over contiguous ranges. That requires
a non-owning contiguous view type. `std::span` provides exactly that and became standard in
C++20.

Supporting C++17 would mean shipping a compatibility span, or depending on an external one.
Both options put a view type — the most fundamental type in the library — outside the
standard, and force conversion boundaries on users who already have `std::span`.

# Decision

C++20 is the minimum supported language version. Precept uses `std::span` directly and does
not reinvent, vendor, or wrap a compatibility span.

# Alternatives considered

Issue #1 records that C++20 was chosen mainly so `std::span` is not reinvented, and issue
#5 records that a C++17 compatibility span is a non-goal; the first two entries follow from
those. The C++23 comparison was reconstructed while drafting this ADR and is open to
correction in review.

* **C++17 with a bundled compatibility span** — widens compiler support, but adds a
  foundational type Precept would have to maintain, and creates conversion friction with
  users' existing `std::span`. Rejected: it contradicts building thinly on the standard
  library.
* **C++17 with a dependency on an external span implementation** — breaks the zero consumer
  dependencies goal recorded in [ADR-0002](adr-0002-header-only.md). Rejected.
* **C++23 as the minimum** — some later facilities would be convenient, but compiler and
  toolchain availability is meaningfully worse and nothing in the v0.1 scope requires it.
  Rejected as premature.

# Consequences

* Users on C++17 or earlier cannot adopt Precept. This is accepted.
* CMake targets express the requirement with `cxx_std_20` so the requirement propagates to
  consumers instead of failing later with obscure errors.
* Precept interoperates with any code that already uses `std::span`, with no conversion
  layer.
* Other C++20 facilities may be used where they help, but the C++20 baseline exists for
  `std::span`; adopting anything with a heavier cost still needs its own justification.

# Status

Accepted.
